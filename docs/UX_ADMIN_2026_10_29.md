# UX administration — navigation et vue d’ensemble, 29 octobre 2026

## Jalon livré

`AdminShell.svelte` porte désormais le header, le lien vers la médiathèque, le
profil, le passage au contenu et la navigation. La route garde ses requêtes,
actions et panneaux métier. `navigation.ts` fournit la liste unique des douze
rubriques, utilisée pour la navigation et les titres. Aucun nouveau rôle, contrat
API, backend, mécanisme d’authentification ou service permanent.

Sur desktop à partir de 1100 px, les rubriques sont visibles dans une sidebar
persistante, défilante si la hauteur manque. À 1024 px et en dessous, un dialogue
natif réserve la largeur au contenu. Sa fermeture reste fixe et sa liste défile.
Le resize ferme le dialogue avant d’afficher la sidebar et libère le défilement
du document. Une seule navigation est rendue à la fois.

Les rubriques sont regroupées en Serveur, Médiathèque, Accès et Exploitation.
Les anciennes destinations restent identiques, notamment :

- `#overview`, `#general-section`, `#network-section` ;
- `#libraries-section`, `#nodes-section`, `#avatars-section` ;
- `#users-section`, `#groups-section`, `#api-keys-section` ;
- `#tasks-section`, `#backups-section`, `#extensions-section` ;
- `#tasks-section?task=scan-…` pour les détails d’une tâche.

Les clics ordinaires utilisent l’historique de fragments, sans recréer les
panneaux. Après sélection, le focus revient au contenu et le document remonte.
Les clics modifiés restent des liens normaux. Le lien d’évitement ne remplace pas
la rubrique active par un fragment inconnu. Les fragments inconnus affichent la
vue d’ensemble, comme auparavant. Échap restitue le focus au déclencheur mobile.
Les filtres de l’annuaire restent présents après un aller-retour entre rubriques.
Les formulaires ont leur propre cycle de vie existant : aucune promesse nouvelle
de persistance de brouillons n’est faite, notamment pour les réglages généraux.

La vue d’ensemble met en premier le serveur, les Media Nodes, les lecteurs ouverts
et les indexations. Le nombre d’utilisateurs et de bibliothèques reste disponible
comme information secondaire. Sur téléphone, ces indicateurs occupent deux
colonnes au lieu d’une longue pile. Les détails d’activité, anomalies de scan,
nœuds et informations techniques restent consultables. Les erreurs d’activité et
de chargement des Nodes affichent un état inconnu et une explication ; elles ne
sont pas présentées comme une liste vide réussie. Une requête de santé encore
indisponible ne prétend plus que le serveur est nécessairement hors ligne.

Les composants utilisateurs, groupes et sauvegardes déjà modifiés dans le
worktree sont conservés. La refonte interne de leurs formulaires et des tâches
reste un chantier distinct.

## Validation reproductible

Depuis `apps/web` : `npm run check`, `npm run lint`, `npm test`, `npm run build`.
Le check conserve l’avertissement préexistant `CatalogGrid.svelte:90`.

Résultat local : check sans erreur, lint et build statique réussis, 177 tests
unitaires réussis dans 29 fichiers. `browser-ux-admin.cjs` : 23 scénarios réussis
(dont 192 sélections de rubrique dans la matrice principale).
`browser-ux-foundations.cjs` : 25 scénarios réussis, aucune anomalie restante.
Chrome 156.0.8078.48 Windows headless. Captures desktop, mobile, paysage,
bibliothèques et diagnostics indisponibles inspectées.

Après le build, depuis `apps/web` :
`npx vite preview --host 127.0.0.1 --port 5182`.
Depuis le dépôt : `node scripts/browser-ux-admin.cjs`.
Variables optionnelles : `MEDIA_UI_URL`, `MEDIA_REPORT_DIR`.

Le banc utilise les vraies routes/composants du build et des réponses API
synthétiques explicites. Il parcourt les douze rubriques à 320, 360, 390, 430,
768, 1024, 1440 et 1920 px dans les deux thèmes. Contrôles : rendu et débordements,
menu clavier/Échap/focus, sélection active, remontée du document, précédent/suivant,
conservation du filtre utilisateurs, ouverture/fermeture de l’éditeur bibliothèque,
liens profonds d’une tâche, passage mobile vers desktop, toucher paysage,
fragments inconnus, états vide/chargement/erreur/reprise, données de diagnostic
indisponibles, navigation anglaise et refus UI d’un compte `user`.
Ce dernier cas ne constitue pas une nouvelle preuve d’autorisation backend.

Preuves locales : `target/ux-admin/report.json`, captures et dossier `before/`.
Les captures de l’aperçu n’affichent que les données synthétiques du banc.
Pas de nouvelle preuve Core/Node, NAS, Authentik, téléphone physique ou audit WCAG
exhaustif ; pas de mesure comparative de performance.

Non-régression : `node scripts/browser-ux-foundations.cjs` ; navigation de
`scripts/browser-extension-catalogue-ui.cjs` adaptée aux deux compositions.
Les scripts Core `browser-series.cjs` et `browser-distributed.cjs` n’essaient plus
d’ouvrir le bouton mobile lorsqu’une sidebar desktop est déjà visible ; leur
exécution réelle nécessite leur serveur de test préparé.

Le script historique complet des extensions a été exécuté mais s’arrête sur
« Actualiser les dépôts », un ancien sélecteur absent de `AdminExtensions.svelte`
(composant non modifié dans ce jalon). Il ne constitue donc pas une preuve de
réussite du parcours complet d’installation/configuration. Les premières fixtures
du script omettaient aussi `sessions` et `keys`, corrigées pour le banc de
navigation. Le mode ciblé `MEDIA_UI_NAVIGATION_ONLY=1` couvre uniquement le shell
et écrit `target/extension-catalogue-ui/navigation-report.json` ; le rapport
historique `report.json` éventuellement présent n’est pas une preuve courante.
